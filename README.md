# Telegram → Google Sheets (R + Apps Script)

## 1. Google Sheet
Создайте Google Таблицу «Учёт наборов» и перенесите таблицу OneNote. Название вкладки: `Учёт наборов`. Заголовки должны быть в строке 1. Столбец B — `rs`, столбец E — `Синтол, шт`. **Важно:** в E должны быть обычные целые числа (`7`), не формулы и не текст (`7 (комментарий)`). Примечания перенесите в столбец H. Сначала используйте тестовую копию таблицы.

## 2. Apps Script
Откройте «Расширения → Apps Script» из Google Таблицы, вставьте `Code.gs`. В «Project Settings → Script properties» добавьте `INVENTORY_API_KEY` со случайным значением длиной минимум 32 символа (`openssl rand -hex 32`). Запустите функцию `setSecretOnce` вручную, предоставьте доступ к таблице. Затем «Deploy → New deployment → Web app», **Execute as: Me**, **Who has access: Anyone**. Скопируйте URL `/exec`.

Внимание: это публично доступный по HTTPS endpoint с секретом в JSON POST. Секрет не публикуйте; сама таблица при этом публичной не становится. Для строгой аутентификации вместо него нужен Sheets API и сервисный аккаунт. После изменения кода Apps Script обновляйте развертывание: Manage deployments → Edit → New version → Deploy.

## 3. Telegram
Создайте бота через @BotFather, добавьте в группу, через `/setprivacy` → `Disable` разрешите читать обычные сообщения с фото (или назначьте администратором). Получите ID супергруппы (`-100...`) через getUpdates. Бот принимает сообщения только из настроенного `TELEGRAM_CHAT_ID`.

## 4. Запуск Docker
```bash
unzip sheets_inventory_bot.zip
cd sheets_inventory_bot
cp .env.example .env
# Заполните секреты и URL в .env
mkdir -p persistent
chmod 600 .env
docker compose up -d --build
docker compose logs -f --tail=100
```

Сначала оставьте `DRY_RUN=true`. Отправьте фото коробки Синтол в группу с подписью `#закончилось`, нажмите «Подтвердить». Бот должен ответить `ТЕСТ`, ничего не изменив в Google Sheets. Затем проверьте работу на тестовой копии с `DRY_RUN=false`, только потом направьте бота в рабочую таблицу. Для перечитывания .env выполните `docker compose up -d --force-recreate`.

## 5. Поведение / ограничения
- Бот ищет ровно один rsID на фото; только наборы **Синтол**. ТестГен пока не списывает, чтобы случайно не уменьшить неверный столбец.
- Кнопками может пользоваться только отправитель исходного фото. Повторные запросы сверяются с журналом `_bot_log` по уникальному `request_id`; Apps Script использует LockService для конкурентных запросов.
- Перед списанием повторно проверяется текущее количество. При изменении остатка со времени появления кнопки операция останавливается.
- Не изменяет сроки годности, примечания и количество другого производителя.
- OCR может ошибаться; **проверяйте rsID перед подтверждением**.
- Запись в ячейку и запись в журнал не являются единой транзакцией. При проблеме связи сверяйте значения и `_bot_log`, прежде чем повторять операцию.
- Не публикуйте `.env`, токен Telegram, ключ Apps Script; храните резервную копию таблицы.


## Исправление отсутствующего пакета httr2

После замены Dockerfile **обязательно пересоберите образ** (перезапуск контейнера не устанавливает пакеты):

```bash
docker compose down
docker compose build --no-cache --progress=plain
docker compose run --rm --entrypoint Rscript inventory-bot -e 'library(httr2); library(jsonlite); library(DBI); library(RSQLite); library(tesseract); cat("Dependencies OK\n")'
docker compose up -d
docker compose logs -f --tail=100
```

Убедитесь, что в логах сборки появилось `All R dependencies installed successfully`.
Теперь подпись фотографии должна содержать `#закончилось`.
