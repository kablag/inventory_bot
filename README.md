# Telegram bot для учета партий в Google Sheets

Бот принимает фотографии с подписью `#закончило`, распознает этикетку через Xiaomi-OCR-0 в Ollama и предлагает списать одну штуку из партии, точно найденной по `rsID + Годен до`.

## Таблица

Вкладка по умолчанию называется `Учёт наборов`; имя можно изменить в `CFG.sheetName` файла `Code.gs`. Заголовки находятся в строке 1, данные — в строках ниже:

| Колонка | Поле | Использование ботом |
|---|---|---|
| A | ID по dbSNP | Только чтение |
| B | rs | Поиск партии и общего остатка |
| C | Сокращенное название | Подпись подтверждения |
| D | Годен до | Точное совпадение партии |
| E | Количество (1 шт = 100 реакций) | Списание; целое неотрицательное число |
| F | Синтол, шт (старое) | Не изменяется |
| G | тестген | Не изменяется |
| H | профиль | Только чтение |
| I | комментарии | Только чтение |

Остаток по набору/`rsID` вычисляется ботом как сумма E по всем строкам с этим `rsID`. Для списания должна существовать ровно одна строка с точной парой `rsID + дата`; ни одной строки — отказ, несколько — ошибка неоднозначности. Даты в таблице должны быть настоящими датами Google Sheets либо отображаться как `ДД.ММ.ГГГГ`.

Скрипт создает скрытый журнал `_bot_log`: `request_id`, время, пользователь, `rsID`, срок годности, остаток партии до/после и общий остаток до/после. Повторный запрос с тем же `request_id` не списывает повторно.

## Apps Script

Откройте **Расширения → Apps Script** из таблицы, замените содержимое редактора файлом `Code.gs`. В Project Settings → Script properties добавьте `INVENTORY_API_KEY` со случайным значением длиной не менее 32 символов. Запустите `setSecretOnce`, выдайте доступ к таблице. Затем разверните Web app: **Execute as: Me**, **Who has access: Anyone** и укажите URL `/exec` в `.env`.

После изменения Apps Script обновите версию развертывания через **Manage deployments → Edit → New version → Deploy**.

## Ollama

Убедитесь, что модель доступна в Ollama:

```sh
curl http://127.0.0.1:11434/api/tags
```

В `.env` задайте `OLLAMA_URL` и точное имя модели из `/api/tags`, например `longwayxu/xiaomi-ocr-0:bf16`. Для Docker Desktop на Windows `http://host.docker.internal:11434` обычно указывает на Ollama хоста. Если Ollama слушает только `127.0.0.1`, настройте ее на прослушивание интерфейса, доступного контейнеру.

Модель получает изображение целиком и возвращает JSON с полным текстом и структурированными полями: продукт, ген, `rsID`, серия, срок годности, красители, хранение и дополнительные данные. Ответ отправляется в чат для проверки. Пустая/неразобранная дата или несколько найденных пар требуют ручного ввода `rsID ДД.ММ.ГГГГ`; списания до ручного уточнения нет. Пользоваться кнопкой подтверждения может только автор исходного фото.

## Запуск

```sh
cp .env.example .env
# Заполните Telegram token/chat id, URL Apps Script и API key.
docker compose up -d --build
docker compose logs -f --tail=100
```

Оставьте `DRY_RUN=true` для проверки OCR и потока подтверждения. Перед рабочим запуском проверьте списание на копии таблицы и установите `DRY_RUN=false`.

## Поведение и ограничения

- После появления кнопки остаток партии проверяется повторно; изменившаяся партия делает заявку устаревшей.
- Списывается только E и только на одну единицу. F и G остаются без изменений.
- Изображение и JSON OCR не подтверждают точность распознавания сами по себе; дата и `rsID` видны в сообщении подтверждения.
- Не публикуйте `.env`, Telegram token или ключ Apps Script.
